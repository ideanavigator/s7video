# Baseline risk map

The areas where a mistake hurts users most, what protects them today, and what a reviewer must check
when a pull request touches them. A diff that touches a row here gets that row's checks in its review
artifact. Areas marked _planned_ do not exist yet; the rule applies from the first ticket that builds
them.

## Risk table

| Area                                   | Files                                                                                                                                                                                                                                        | What can go wrong                                                                                                                                                                       | Review requirement                                                                                                                                                                    |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider keys and secrets              | `apps/server/src/settingsSecrets.ts`, `apps/server/src/secrets/*`, `apps/server/src/auth/ServerSecretStore.ts`, `packages/secret-provider-core`                                                                                              | A key lands in `settings.json`, a log, the web client or telemetry.                                                                                                                     | Secret fields are registered as secret; values reach the client only redacted, with a test. No key in logs or errors. User keys for bring-your-own-key mode go to the macOS Keychain. |
| File system access                     | `apps/server/src/workspace/WorkspaceFileSystem.ts`, `WorkspacePaths.ts`, `apps/server/src/assets/AssetAccess.ts`, `apps/server/src/attachmentStore.ts`                                                                                       | An agent, a crafted project file or a URL reads or writes outside what the user opened. `filesystem:read` can read any file the user can, and signed asset URLs are bearer credentials. | Relative paths and all writes go through the workspace path rules. New file routes say who can mint the URL and how long it lives. Tests cover `..`, symlinks and absolute paths.     |
| Original media                         | _planned_: project `media/raw/`                                                                                                                                                                                                              | Originals get modified, moved or deleted.                                                                                                                                               | No code path opens originals for writing. Proxies, thumbnails and renders go to their own folders and can be rebuilt.                                                                 |
| Agent permissions and tools            | `apps/server/src/mcp/McpToolAccess.ts`, `apps/server/src/auth/RpcAuthorization.ts`, `apps/server/src/auth/EnvironmentAuth.ts`, `apps/server/src/policy/*`                                                                                    | A tool or RPC lets an agent or a paired client act above its grant.                                                                                                                     | Every new RPC declares its scope; every new MCP tool declares its access level. Denied-case test.                                                                                     |
| Subprocesses and terminal              | `apps/server/src/processRunner.ts`, `apps/server/src/terminal/*`, provider drivers in `apps/server/src/provider/*`                                                                                                                           | Shell injection, orphaned processes, a kill that hits the wrong process.                                                                                                                | Argument arrays only; no shell strings built from input. Processes are tracked by the PID captured at spawn and cleaned up on cancel.                                                 |
| Data folder and T3 Code's data         | `packages/shared/src/devHome.ts`, `apps/server/src/config.ts`, desktop user-data paths                                                                                                                                                       | s7video reads, migrates or deletes an installed T3 Code's threads, settings or Electron profile (`~/.t3`).                                                                              | s7video uses only its own folder (`~/.s7video`, dev `~/.s7video/dev`). No code reads or writes `~/.t3`; no migration or cleanup of T3 data.                                           |
| App database migrations                | `apps/server/src/persistence/Migrations/*`, `Migrations.ts`, `OrchestrationEventStore.ts`                                                                                                                                                    | A migration loses threads or cannot run on an old database.                                                                                                                             | Migrations are append-only and forward-only, tested against a database from the previous version. Never edit a released migration.                                                    |
| Edit document (`edit.json`) migrations | _planned_: schema in `packages/contracts`                                                                                                                                                                                                    | A schema change makes old edits unreadable or silently changes them.                                                                                                                    | Version field bumped; a forward migration with a test that opens a stored older document and checks the timeline is unchanged.                                                        |
| Checkpoints and undo                   | `apps/server/src/checkpointing/CheckpointStore.ts`                                                                                                                                                                                           | An edit cannot be undone, or undo restores the wrong state.                                                                                                                             | Each agent edit ends in a checkpoint. Tests cover apply, undo and redo across a restart.                                                                                              |
| Render pipeline                        | _planned_: engine and FFmpeg bundle (S7V-016)                                                                                                                                                                                                | Out-of-sync audio, dropped or duplicated frames, wrong colour, a GPL build of FFmpeg, unbounded temp files.                                                                             | Golden media tests ([media-standards.md](media-standards.md)). FFmpeg is the LGPL build, dynamically linked. Renders are cancellable and clean their temp files.                      |
| Updater                                | `apps/desktop/src/updates/*`, `apps/server/src/desktopUpdate/*`, `apps/server/src/cloud/{selfUpdate,pinnedRuntime,npmRelease,bootService}.ts`, `apps/server/src/cli/update.ts`                                                               | An update comes from the wrong source, is not verified, or bricks the install. Some paths still point at T3 Code's releases (see [docs/FORK.md](../FORK.md#still-contacts-t3)).         | Update URLs come from config. Downloads are HTTPS and checked (signature or `SHA256SUMS`). A failed update leaves the current version running.                                        |
| Network egress and telemetry           | `apps/server/src/telemetry/AnalyticsService.ts`, `packages/shared/src/otelEnvironment.ts`, `apps/server/src/outboundHttp.ts`, `apps/server/src/provider/ModelManifest.ts`, `packages/provider-acp-registry/src/server/AcpRegistrySupport.ts` | Data leaves the machine that [PRIVACY.md](../../PRIVACY.md) does not allow, or reaches T3 Code's servers.                                                                               | Every new host is listed in the PR with what is sent. Telemetry is off by default and has no default destination.                                                                     |
| Electron shell                         | `apps/desktop/src/preload.ts`, `apps/desktop/src/ipc/*`, `apps/desktop/src/preview/*`, `apps/desktop/src/permissions/*`                                                                                                                      | Web content gains Node or IPC access it should not have; the in-app browser leaks into the app.                                                                                         | No widened preload surface without a reason; IPC handlers validate input; remote content stays sandboxed.                                                                             |
| Licences                               | `third-party-licenses.config.json`, `scripts/sync-third-party-license-notices.ts`, `third-party-licenses/`                                                                                                                                   | A blocked licence or a missing notice ships.                                                                                                                                            | New items are on the allowlist and in the ticket's Licence & Assets table; notices regenerated.                                                                                       |
| Brand and config                       | `apps/web/src/branding.ts`, desktop app metadata; `s7video.config.ts` from S7V-003                                                                                                                                                           | Hard-coded names, colours or URLs creep back in, or point at T3 Code.                                                                                                                   | Apply [theming-and-config.md](theming-and-config.md).                                                                                                                                 |
| Ticket tooling                         | `scripts/planning.ts`, the planning repo's `tickets/test-map.json`                                                                                                                                                                           | Verification commands drift from what the ticket claims.                                                                                                                                | The reviewer compares the ticket's ACs and Verification Commands with the test map and records gaps.                                                                                  |

## Review focus right now

1. Sprint 01 changes shared upstream files; check every row above that a removal or rebrand touches.
2. Until S7V-003 and S7V-013 land, the app still shares `~/.t3` with T3 Code and still contacts T3's
   update and analytics endpoints. Treat any change near those paths as critical-risk.
3. The planned rows (original media, edit document, render pipeline) get their tests written with the
   first ticket that creates them, not later.
